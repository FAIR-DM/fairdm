    fairdm.contrib.contributors.plugins.tab_people¶

    Adding a person on a record’s Contributors tab, in steps drawn in one sheet.

    The steps are: find someone in the portal or by ORCID iD, then (for someone not in the portal) who ORCID has under their name, the name checked, their affiliation on the record, and their roles. Each step is a GET that answers with the next step, carrying what the earlier ones learned in its address, and the last step posts.

    portal_organization(entry)¶

    Return the portal’s organization for one picked from ORCID or ROR, making it if need be.

    It is found by its ROR ID, then by its name, and made only when neither matches.

    Args: entry: The organization’s name and ror (an empty string when it has none).

    Raises: RegistryUnavailable: ROR could not be asked for an organization to make.

    (‘stage’, ‘aq’, ‘org’, ‘ror’, ‘org_name’, ‘none’, ‘from’)

    What the affiliation steps add to the address: which of them it is (stage), the name searched for (aq), and the organization picked: one in the portal (org), one from ROR or an ORCID record (ror with its org_name), one by name alone (org_name), or none (none).

    get(request, *args, **kwargs)¶

    Draw the next step for a chosen person, or for someone new.

    Someone new is given by ORCID iD, or by name. An iD goes straight to their affiliation, offering the affiliations on their ORCID record. A name first shows the people ORCID finds by that name (“Do you mean?”), which a name and an affiliation narrow (find and at), to pick from or to skip. Skipping (confirm) asks for the given names and family name, guessed from the name, before the affiliation. A name or an iD typed in the search (via=search) comes straight here, and Back returns to the search.

    Args: request: The request. *args: Unused URL arguments. **kwargs: Unused URL keyword arguments.

    orcid_person(orcid_id, typed, via, narrowed)¶

    Continue with someone picked from ORCID: the person the portal holds, or a new one.

    Args: orcid_id: The ORCID iD picked. typed: The names typed so far. via: Where the step was reached from. narrowed: The name and affiliation the search was narrowed by.

    affiliation_flow(person, new_name, back_url)¶

    Draw the steps that find the person’s affiliation on this record, then their roles.

    The first step lists the organizations on their ORCID record or their profile, then the portal’s, filtered by a search. A name that isn’t in the portal is a New row, which leads to what ROR has under that name (“Do you mean?”), to pick from or to add by name alone. Picking any of them leads to the roles step, with the organization shown as their affiliation.

    Args: person: The person the portal holds, or None for someone new. new_name: The new person’s names. back_url: Where Back returns to.

    affiliation_results(person, new_name, here, query)¶

    Return the organizations the affiliation step lists for a search, in their groups.

    Args: person: The person the portal holds, or None for someone new. new_name: The new person’s names. here: The address of this step. query: What was typed in the affiliation search.

    Returns: The context of affiliation_results.html: orcid (the organizations on the person’s ORCID record), theirs (those on their profile), others (the portal’s, up to twelve) and new_row, each with the address of the roles step it leads to, and problem when ORCID could not be asked.

    picked_affiliation(data)¶

    Return the organization picked in the affiliation steps, without making it.

    Args: data: The step’s query or the posted form, holding org, ror and org_name.

    Returns: (organization, entry): the portal’s organization, or None, and for one not in the portal yet entry, its name and ror, that portal_organization makes it from. Both None for no affiliation.

    Args: person: The person the portal holds, or None for someone new. new_name: The new person’s names. here: The address of the affiliation step. head: The sheet’s heading.

    orcid_matches_step(typed, via, narrowed, only_list=False, problem='')¶

    Draw who ORCID finds under a name, to pick from or skip.

    Args: typed: The names first given, which Back to the search returns with. via: "search" when the names were typed in the search, where Back then returns. narrowed: The name (find) and affiliation (at) the user narrowed the search to, the names first given when there are none. only_list: Whether to answer with the list of matches alone, as the narrowing fields ask for while the user types. problem: What went wrong asking ORCID for a person picked from the list.

    confirm_name_step(typed, narrowed, via, given=False)¶

    Draw the step that asks for someone’s given names and family name.

    A name can’t be split into the two reliably, so the step guesses (the last word is the family name) and the user corrects it. It follows Add by name alone, guessing from the name last searched. Back from the affiliation step returns to it with the names given.

    Args: typed: The given names and family name typed so far. narrowed: The name and affiliation the search was narrowed by. via: Where the step was reached from. given: Whether the names were already given, so not guessed.
