{% extends "detail_view.html" %} {% load i18n static humanize thumbnail fairdm %} {% comment %} The overview page every core record shares: project, dataset, sample and measurement. One anatomy on all four, so a reader finds the same fact in the same place. A header band in the record's colour says what it is, who made it, its key facts and its headline figures. Beneath it the content sits in a wide column, and the facts a reuser checks before going further sit beside it: how to cite it first, then one fact sheet, then the people credited, then what is particular to the record. Below `lg` the columns stack, content first. A record with an image shows it filling the header's trailing side, opening at full size. A record without one shows its icon, with the sign-in pages' ruled grid on the trailing side. There is no central editing menu. Each part of the record is edited from the panel that shows it, through the `edit` links (`fairdm.core.editing.edit_links`), drawn only for someone who may. Each record's own template extends this one and fills blocks. A sample or measurement type extends its record's template the same way, using `{{ block.super }}` to add to a block and keep what is there. Blocks, in page order: overview.notices alerts above the header, so they are read first overview.image header: the record's icon, shown when it has no image overview.badges header: type, status and access overview.name header: the name inside the heading overview.byline header: the people behind the record, by name overview.facts header: a line of key facts, label then value, as
  • items overview.keywords header: keywords, with their own Edit overview.actions header: Cite and Share, then the header's own Edit overview.manage the header's Edit, which opens the details; fill it to add buttons overview.figures header foot: the headline figures, or a measurement's result overview.main the wide column; each record fills it with its own blocks overview.side the facts column, which holds, in this order: overview.readiness what the team still has to add (team only) overview.cite how to cite it overview.details the fact sheet: details, identifiers, funding, machine access overview.details_extra rows added to the details section overview.timeline key dates, where a record shows them beside the content overview.people everyone credited, by name with their roles overview.record_facts what is particular to the record (a dataset's publications) overview.chart_library the ECharts script; replace it to serve ECharts yourself The side-column blocks draw the shared `c-overview.*` components from the context every overview plugin provides, so a record's template only overrides them to change what they say. {% endcomment %} {% block head %} {{ block.super }} {% if json_ld %} {% comment %} schema.org JSON-LD for search engines and harvesters.
