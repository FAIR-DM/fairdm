{% extends "detail_view.html" %} {% load i18n static humanize thumbnail %} {% comment %} The overview page every core record shares: project, dataset, sample and measurement. One anatomy on all four, so a reader finds the same fact in the same place: notices, the header (badges, name, a line placing the record, keywords, actions), a strip of figures, then the content in a wide column with the facts a reuser checks in a narrow column beside it. Below `lg` the columns stack, content first. Each record's own template extends this one and fills blocks. A sample or measurement type extends its record's template the same way, using `{{ block.super }}` to add to a block and keep what is there. Blocks, in page order: overview.notices alerts above the header, so they are read first overview.image header: the record's image, a banner across the top of the card overview.icon header: the record's icon, beside the name when it has no image overview.badges header: status badges overview.name header: the name inside the heading overview.byline header: the people behind the record (a project's leads, a dataset's creators), avatar and name, no caption overview.keywords header: keywords overview.actions header: buttons (Cite and Share by default, then the Manage menu) overview.manage the Manage menu, drawn by ``; fill it to add entries through the component's slot, and put any button that belongs before the menu in front of it overview.figures the figures strip overview.main the wide column; each record fills it with its own blocks overview.side the facts column, which holds, in this order: overview.readiness what the team still has to add (team only) overview.details what it belongs to, licence, status, dates, how machines reach it overview.details_extra sections inside Details, e.g. a project's timeline overview.timeline key dates in the record's life, where they have their own card overview.people everyone credited, the people named in the header included overview.identifiers DOI, IGSN and the rest, the team's own ID and the portal ID overview.funding funding awards, on records that carry them overview.cite how to cite it overview.record_facts cards particular to the record (a dataset's publications) overview.chart_library the ECharts script; replace it to serve ECharts yourself The facts-column blocks draw the shared `c-card.*` components from the context every overview plugin provides, so a record's template only overrides them to change what they say. {% endcomment %} {% block head %} {{ block.super }} {% if json_ld %} {% comment %} schema.org JSON-LD for search engines and harvesters.
