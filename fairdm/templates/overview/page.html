{% extends "detail_view.html" %} {% load i18n static thumbnail %} {% comment %} The overview page every core record shares: project, dataset, sample and measurement. One anatomy on all four, so a reader finds the same fact in the same place: the header (badges, name, a line placing the record, keywords, actions), notices, a strip of figures, then the content in a wide column with the facts a reuser checks in a narrow column beside it. Below `lg` the columns stack, content first. Each record's own template extends this one and fills blocks. A sample or measurement type extends its record's template the same way, using `{{ block.super }}` to add to a block and keep what is there. Blocks, in page order: overview.image header: the record's image, or its icon overview.badges header: status badges overview.meta header: the line placing the record (parents, dates, IDs) overview.byline header: who made it overview.keywords header: keywords overview.actions header: buttons (Cite and Share by default) overview.notices alerts above the figures overview.figures the figures strip overview.main the wide column; each record fills it with its own blocks overview.side the facts column, which holds, in this order: overview.readiness what the team still has to add (team only) overview.cite how to cite it overview.identifiers licence, access, identifiers, API overview.people everyone credited overview.record_facts cards particular to the record (funding, publications, versions) overview.parent what it belongs to overview.dates details and dates overview.chart_library the ECharts script; replace it to serve ECharts yourself The facts-column blocks draw the shared `c-card.*` components from the context every overview plugin provides, so a record's template only overrides them to change what they say. {% endcomment %} {% block head %} {{ block.super }} {% if json_ld %} {% comment %} schema.org JSON-LD for search engines and harvesters.
