Mirrors `project/project_card.html` element for element and draws the same `record-card` classes from `css/fairdm.css`, so the two listings show one card. Only the accent colour differs, through `record-card--dataset`. A change to the shape of either card belongs in both, or the two drift apart. Rendered directly rather than through `cotton/components/object_card.html`: that component is Bootstrap-era markup and none of its classes resolve against `mvp/static/css/django-mvp.css`, the only stylesheet the portal loads. The card reflows on its OWN width, not the viewport's — `record-card` sets `container-type: inline-size` and the breakpoints in `css/fairdm.css` are `@container` queries. Viewport breakpoints would be wrong the moment the card is drawn anywhere narrower than a full listing row, such as a plugin panel. That stylesheet is linked once per page from `fairdm/templates/base.html`, never from here: a `` in this template would be emitted once per card. Everything the card draws is loaded by `DatasetQuerySet.with_list_data()` and `with_contributors()`; adding a field here that neither prefetches puts one query per card back on the page. {% endcomment %} {% comment %} The reflow lives on this wrapper, not on `.record-card` itself. A container query is answered by an ancestor container, so the element carrying `container-type` can never respond to its own width. {% endcomment %}
