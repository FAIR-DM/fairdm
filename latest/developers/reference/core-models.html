Core models#

This page lists the fields, choices, managers and rules of the two fixed core models, Project and Dataset, and the fields they share with samples and measurements. It does not cover the two models you extend, which are on Sample model and Measurement model, or why the four levels exist, which is in The core data model. Methods are listed by name only. Their signatures are on the Python API page.

Import the models from their own modules:

from fairdm.core.dataset.models import Dataset
from fairdm.core.project.models import Project

fairdm.core.models also re-exports Project, Dataset, Sample and Measurement.

        erDiagram
    Organization |o--o{ Project : owns
    Project |o--o{ Dataset : holds
    Dataset ||--o{ Sample : holds
    Dataset ||--o{ Measurement : holds
    Sample ||--o{ Measurement : "is measured by"
    Sample }o--o{ Sample : "SampleRelation"

Deletion#

Deleting a project deletes its datasets. A project that still has a public dataset cannot be deleted. The attempt raises PublicDatasetsProtect, which carries the blocking datasets.

Descriptions, dates and identifiers#

A project and a dataset each carry typed rows. A row model exists for each pair, such as ProjectDescription and DatasetDate. Every row model links back to its record by related and is reached from the record by descriptions, dates or identifiers.

Rows

type is drawn from

value

Rules

Descriptions

The description types

Text of at most 20,000 characters.

One row of each type for each record.

Dates

The date types

A partial date: a year, a year and month, or a full date. See Model fields.

One row of each type for each record. The end may not be before the start.

Identifiers

The identifier types

Text of at most 255 characters.

One row of each type for each record. The value is unique across every kind of record.

type is a ConceptField limited to the record’s collection of the vocabulary, and holds the concept’s address: the vocabulary’s address, a slash and the identifier listed below. The start and end types are start and end for a project, ProjectDate.START_TYPE and ProjectDate.END_TYPE, and collection-start and collection-end for a dataset. The end is compared with the start at the coarser of their two precisions.

The types each record accepts, by identifier, in the order its collection lists them:

Record

Descriptions

Dates

Identifiers

Project

abstract, introduction, background, objectives, expected-output, conclusions, other

start, end

doi, grant-number, proposal-id

Dataset

abstract, methods, series-information, technical-info, other

available, collection-start, collection-end, submitted, published, withdrawn

doi

The roles a person or organization can hold on a record come from the contributor roles vocabulary, by identifier:

Record

Roles

Project

creator, project-leader, project-member, project-manager, contact-person, other

Dataset

creator, contact-person, data-collector, data-curator, data-manager, editor, producer, related-person, researcher, project-leader, project-manager, project-member, supervisor, work-package-leader, rights-holder, other

The vocabularies’ addresses are constants in fairdm.core.vocabularies, and get_type_concepts() on a row model returns the concepts its collection offers. See Controlled vocabularies.

Permissions#

Both models declare these permissions beside Django’s four. Who holds them on a record is decided by the level a person has on it, as described in How access to a record is decided.

Model

Permissions

Project

add_contributor, modify_contributor, modify_metadata, change_project_metadata, change_project_settings

Dataset

add_contributor, modify_contributor, modify_metadata, import_data, can_publish, change_dataset_metadata, change_dataset_settings

Both are ordered by -modified and indexed on modified.
