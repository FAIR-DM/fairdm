    Components¶

    FairDM ships Cotton components that a portal’s templates can use. This page lists each one with its attributes, its slots and what it renders. It does not say where a component sits on a page. The pages that use them are described in Overview page blocks, Home page and Entrance pages.

    Every component is written as a tag named after its template path, with / turned into . and _ turned into -. overview/sheet.html is <c-overview.sheet>. An attribute that takes a Python value, such as a list, a dictionary or a record, is written with a leading colon: <c-overview.people :people="people" />. Most components also take class, which adds classes to the outer element, and pass any other attribute to it.

    The tables give each attribute’s type, its default and what it accepts. A blank default means the attribute is not set.

    Actions¶

    c-actions.create-new¶

    A dropdown button labelled “Create new” with a link to the project create page and one to the dataset create page. It renders only for a signed-in user and reads user from the template context, so it takes no attributes.

    c-actions.pending¶

    A disabled button for something a portal does not offer yet. It never submits or links. Its title and a screen-reader-only line carry the reason.

    Attribute

    Type

    Default

    Accepts

    label

    string

    The button’s text.

    icon

    string

    An icon name, drawn before the text.

    reason

    string

    What the button will do once it exists.

    variant

    string

    outlined

    primary for a filled button.

    size

    string

    sm

    xs or sm.

    		 
    <c-actions.pending label="Publish" icon="upload" reason="Publishing is not available yet." />

    Overview page components¶

    The shared overview page and each record’s template draw their panels with <c-overview.NAME> tags. A panel carries a data-card attribute that tests and scripts can find it by. The attributes below are the data the overview plugins build, listed in Overview plugins, and the blocks that draw each are listed in Overview page blocks.

    c-overview.panel¶

    A section of an overview page: a heading with an optional count, the panel’s own Edit control and a link to the full list, then its content.

    Attribute

    Type

    Default

    Accepts

    title

    string

    The heading.

    count

    string

    A count beside the heading.

    edit_url

    string

    The editing page for what the panel shows. Leave it empty for anyone who may not edit it, and no control is drawn.

    edit_text

    string

    Edit

    The Edit control’s text.

    edit_icon

    string

    edit

    Its icon.

    edit_label

    string

    Its accessible name, when the text alone does not say what is edited.

    more_url

    string

    The full list, linked as “See all”.

    more_text

    string

    See all

    The link’s text.

    sub

    string

    A line under the heading.

    side

    boolean

    False

    A side-column panel, which is tighter.

    id, class

    string

    On the section.

    Slot

    Holds

    default

    The content.

    head

    Extra controls in the heading row.

    		 
    <c-overview.panel title="Datasets" count="3" more_url="{{ urls.datasets }}"
                  edit_url="{{ add_url }}" edit_text="Add dataset" edit_icon="add">
  …
</c-overview.panel>

    c-overview.edit¶

    The small Edit control a panel carries for the part of the record it shows. It draws nothing when href is empty.

    Attribute

    Type

    Default

    Accepts

    href

    string

    The editing page, usually one of the edit links.

    text

    string

    Edit

    The visible text.

    icon

    string

    edit

    The icon.

    label

    string

    The accessible name, when the text alone does not say what is edited.

    		 
    <c-overview.edit href="{{ edit.identifiers }}" label="Edit identifiers" />

    c-overview.status¶

    A status or access chip in an overview page’s header or fact sheet: a pill with a dot and a light fill in its status colour.

    Attribute

    Type

    Default

    Accepts

    variant

    string

    neutral

    success, warning, error, info or neutral.

    icon

    string

    An icon drawn in place of the dot.

    title

    string

    What the status means, shown on hover.

    		 
    <c-overview.status variant="{{ project.status_badge_variant }}">{{ project.get_status_display }}</c-overview.status>

    c-overview.figure¶

    One headline figure along the foot of the header, linked to its list when href is set.

    Attribute

    Type

    Default

    Accepts

    value

    string

    The figure.

    label

    string

    What it counts.

    href

    string

    The list it counts.

    record

    string

    project, dataset, sample or measurement, which draws the type’s colour beside the label.

    note

    string

    A line under the label.

    Put the figures in a <div class="ov-figures"> in the overview.figures block.

    c-overview.result¶

    A measurement’s result along the foot of the header, in the figures’ place: the value large, its unit, and notes beside it. The notes are the slot: a detection limit, an uncertainty or the instrument. With no slot, nothing is drawn beside the value.

    Attribute

    Type

    Default

    Accepts

    label

    string

    What the value is, such as Result or Concentration.

    value

    string

    The value, already formatted.

    unit

    string

    The value’s unit.

    		 
    <c-overview.result label="Concentration" value="{{ measurement.concentration_ppm|floatformat:'-2' }}" unit="ppm {{ measurement.element }}">
  <span>Detection limit {{ measurement.detection_limit_ppm }} ppm</span>
</c-overview.result>

    Put it in the overview.result block of a measurement type’s template.

    c-overview.cite¶

    How to cite the record as Text, BibTeX or RIS. A switch in the panel’s head picks the format, Copy copies the format on show, and Download saves BibTeX or RIS from the format’s own address. The reader’s last choice is remembered in their browser. The panel’s element id is cite, which the Cite button in every page header jumps to. data-card is citation.

    Attribute

    Type

    Default

    Accepts

    formats

    list

    The ways to take the citation, as the overview plugin’s get_citation_formats() returns them: one entry per format with its key, label, value, url and download. The first entry is shown when the page loads.

    Slot

    Holds

    default

    A note under the citation, such as why it points at this page rather than a DOI.

    c-overview.sheet¶

    The record’s facts in one panel: the details, the identifiers, the funding and how a machine reaches the record, each a section of label-and-value rows. A row with no value shows a dash. The team’s Edit controls sit on the panel and on its Identifiers section, and Delete is its last line. data-card is details, and the Identifiers and Funding sections carry identifiers and funding.

    Attribute

    Type

    Default

    Accepts

    rows

    list

    Dictionaries with label, and one of record (a record, shown by name in its type’s colour, with icon naming the type), badge with badge_variant, date with an optional until for a range, or text with an optional url. A row may also carry note (a line under the value) and warning (draws the value as a warning).

    edit

    dict

    The edit links. details, identifiers and delete are read.

    kind

    string

    The word for the record’s kind, named in the Delete line.

    identifiers

    list

    Dictionaries with type, value and link. A link makes the value a link. Each has a button that copies it.

    portal_id

    string

    The record’s portal ID, with a button that copies it.

    permalink

    string

    The record’s absolute permalink, with a button that copies it.

    local_id

    string

    The team’s own ID for the record.

    funding

    list

    DataCite funding references with funderName, funderIdentifier, awardTitle, awardNumber and awardURI. A funder identifier or award address is linked only when it starts with http. None leaves the section out, and an empty list says none is recorded.

    can_manage

    boolean

    False

    Whether the viewer is on the record’s team. With no funding, the team is told why funding matters.

    api_url

    string

    The record’s REST API address. With none, no API link is drawn.

    Slot

    Holds

    default

    Rows added to the details section, each written as <div><dt>…</dt><dd>…</dd></div>.

    c-overview.people¶

    Everyone credited on the record: the first few by name with their roles, then faces, then a count of the rest linked to the full list. The team gets Manage, which leads to the Contributors tab. With nobody credited, the panel says so. data-card is people.

    Attribute

    Type

    Default

    Accepts

    people

    dict

    named (dictionaries with contributor, roles, more_roles and affiliation), faces, more and total, from get_people().

    all_url

    string

    Where the full list is. It becomes “See all” for a visitor and the link on the count of the rest.

    manage_url

    string

    Where the team changes who is credited, drawn as Manage. Leave it empty for anyone else.

    title

    string

    People

    The heading.

    empty

    string

    No one is credited yet.

    What to say when nobody is credited.

    c-overview.readiness¶

    For the record’s team only: a ring with how much is in place, what is still missing with a Fix link where one exists, and what is done folded away. data-card is readiness.

    Attribute

    Type

    Default

    Accepts

    readiness

    dict

    title, summary, about, items (dictionaries with label, done, url and required, where required set to False marks a recommended item), done, total and ready.

    Slot

    Holds

    default

    An action the checklist leads to, such as the dataset’s Publish.

    c-overview.descriptions¶

    The record’s descriptions. With more than one, each has a tab in the panel’s heading. With one, its label is the heading. With none, the panel is headed “About” and shows the slot. Values are rendered as markdown, and long text folds after a few lines behind “Read more”. data-card is descriptions.

    Attribute

    Type

    Default

    Accepts

    descriptions

    list

    Dictionaries with label and value, in the order the tabs appear.

    group

    string

    A prefix that makes the tabs’ ids unique on the page.

    edit_url

    string

    The descriptions’ editing page, for someone who may edit them.

    Slot

    Holds

    default

    What to show when there are no descriptions.

    c-overview.mix¶

    How many records of each type there are, as bars in the type’s colour, samples and measurements in their own groups, each bar drawn against the largest count.

    Attribute

    Type

    Default

    Accepts

    mix

    dict

    samples and measurements, each a list of (type name, count), and max, from get_type_mix().

    c-overview.history¶

    The steps in a record’s life, oldest first, as a dated timeline: the date on the leading side, then what happened, who did it and a note. A date recorded only to the month is shown as the month, and one recorded only to the year as the year. data-card is timeline.

    Attribute

    Type

    Default

    Accepts

    title

    string

    The heading, such as History.

    steps

    list

    Dictionaries with label, date, day, people and note, from get_timeline(). day is set when the date is a full day. note is rendered as markdown.

    empty

    string

    What to say when there are no steps.

    edit_url

    string

    The key dates’ editing page, drawn as the panel’s Edit for someone who may edit them.

    c-overview.props and c-overview.prop¶

    The fields a sample or measurement type adds, label over value in a grid. c-overview.props is the panel and c-overview.prop is one field in it. A field with no value shows a dash. data-card is properties.

    c-overview.props attribute

    Type

    Default

    Accepts

    title

    string

    The heading, such as Rock properties.

    edit_url

    string

    The editing page for these fields.

    c-overview.prop attribute

    Type

    Default

    Accepts

    label

    string

    The field’s name.

    value

    string

    The value. Without one the slot is drawn, and without either a dash.

    wide

    boolean

    False

    Spans the whole grid.

    text

    boolean

    False

    A longer piece of writing, set as text rather than a figure.

    		 
    {% block overview.properties %}
  <c-overview.props title="Rock properties" edit_url="{{ edit.details }}">
    <c-overview.prop label="Rock type" value="{{ sample.rock_type|capfirst }}" />
    <c-overview.prop label="Mineral content" value="{{ sample.mineral_content }}" wide text />
  </c-overview.props>
{% endblock overview.properties %}

    c-overview.coverage¶

    Where a project’s or dataset’s samples were taken: every located sample the viewer may open on one map, clustered where they crowd, with the counts, the area covered and a “See all” link to the samples list beneath. data-card is coverage. With no located sample, it says there is nothing to map yet and draws no map. The map element carries data-points-url and data-bounds, and js/overview.js fetches the points once the page has drawn. The page sets has_map so MapLibre is loaded.

    Attribute

    Type

    Default

    Accepts

    map

    dictionary

    The page’s sample_map: located, missing, bounds, area, points_url and, on a project, datasets.

    id

    string

    The panel’s id.

    title

    string

    Where the samples come from

    The heading.

    more_url

    string

    The samples list, linked as See all.

    empty

    string

    What to say when no sample has a location.

    		 
    <c-overview.coverage :map="sample_map" id="coverage" more_url="{{ urls.samples }}" />

    c-overview.activity¶

    A project’s or dataset’s recent activity: its lines grouped by day, newest first, each line marked in its record’s colour. data-card is activity. The list is django-mvp-community’s <c-mvp_community.activity.feed>, handed one item per day, and it draws its own empty state when there is nothing to show. FairDM overrides that package’s row, cotton/mvp_community/activity/entry.html, to draw a day, so any other use of the package’s list in a portal draws FairDM’s day row too.

    The actions behind the panel are recorded as not public and read through each record’s own rules. Do not include actstream.urls in a portal’s URLs: some of django-activity-stream’s views show actions that are not public to anyone.

    Attribute

    Type

    Default

    Accepts

    days

    list

    Day items from fairdm.contrib.activity.lines.group_days(), each with day and lines.

    more_url

    string

    The full list, linked as See all.

    		 
    <c-overview.activity :days="activity.days" more_url="{{ activity.more_url }}" />

    c-overview.location¶

    Where a sample was taken or a measurement made: a map with the point marked, and the coordinates written out as decimal degrees in WGS 84 to five places. data-card is location. The map is drawn by js/overview.js with MapLibre, which overview/page.html loads in its overview.map_library block when the context sets has_map.

    Attribute

    Type

    Default

    Accepts

    location

    point

    A point with x (longitude) and y (latitude).

    elevation

    number

    Metres above sea level. Left out when not given.

    uncertainty

    number

    Metres. Left out when not given.

    title

    string

    Location

    The heading.

    label

    string

    The map’s accessible name. Defaults to a sentence about where the sample was taken, with the coordinates.

    empty

    string

    What to say when there is no location. Without it and without a location, nothing is drawn.

    edit_url

    string

    The editing page for the location.

    id

    string

    The panel’s id, which a link in the header can point at.

    Maps and filters in js/overview.js¶

    The script every overview page loads draws a map in each element marked data-map with data-lon and data-lat, with a marker in the record type’s colour. An element marked data-map with data-points-url and data-bounds instead opens on the bounds, fetches GeoJSON points from the address and draws them clustered: selecting a cluster zooms in, and selecting a point opens a popup listing every sample at that spot, each linking to its page. Each map has zoom buttons, scrolls with the page until the reader means to move it, and keeps the tile credits closed behind their (i) button.

    A group of buttons marked data-filter-chips="<list id>" filters the list with that id: each button shows only the rows whose data-type is its data-value, and an empty data-value shows them all. A link marked data-filter-more="<list id>" is hidden while a type is chosen.

    Cards for record and contributor pages¶

    Every card is a <c-card.NAME> tag. Each carries a data-card attribute that tests and scripts can find it by. The dataset, sample and measurement pages, and the person and organization pages, draw these beside the c-overview.* panels.

    c-card.identifiers¶

    Every identifier the record carries as a small table, then the team’s own ID and the portal ID with a button that copies it. data-card is identifiers.

    Attribute

    Type

    Default

    Accepts

    identifiers

    list

    Dictionaries with type, value and link. A link makes the value a link.

    portal_id

    string

    The record’s portal ID.

    local_id

    string

    The team’s own ID for the record.

    permalink

    string

    The record’s absolute permalink, drawn as a row beneath the portal ID with a button that copies it.

    class

    string

    Extra classes on the card.

    c-card.location¶

    Where something is: a map with the point marked, and the coordinates written out as decimal degrees in WGS 84 to five places. The organization page draws it. The map is drawn by js/overview.js, like c-overview.location’s, when the page’s context sets has_map. data-card is location.

    Attribute

    Type

    Default

    Accepts

    location

    point

    A point with x (longitude) and y (latitude).

    elevation

    number

    Metres above sea level. Left out of the card when not given.

    uncertainty

    number

    Metres. Left out of the card when not given.

    title

    string

    Location

    The card’s title.

    label

    string

    The map’s accessible name. Defaults to a sentence about where the sample was taken, with the coordinates.

    empty

    string

    What to say when there is no location. Without it and without a location, nothing is drawn.

    class

    string

    Extra classes on the card.

    c-card.people¶

    Everyone credited on the record, as a grid of faces. Hovering a face shows the name, and each face links to the contributor’s page. With nobody to show, the card says so. data-card is people.

    Attribute

    Type

    Default

    Accepts

    people

    dict

    shown (the contributors to draw), more (how many were left out) and total.

    all_url

    string

    Where the full list is. It becomes a “See all” button and the link on the count of the rest.

    title

    string

    People

    The card’s title.

    empty

    string

    No one is credited yet.

    What to say when nobody is shown.

    Contributors¶

    These components draw the people and organizations credited on a record. Each accepts a Person, an Organization or a Contribution. Given a contribution, it draws the contributor behind it, the roles held on the credit and the organization named on the credit.     Each image comes from the avatar resolver set in MVP_CONFIG["brand"]["avatar_resolver"], described in Settings.
