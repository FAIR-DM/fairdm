Contributor models#

This page lists the models, fields, managers, methods and helper modules of fairdm.contrib.contributors that describe people and organizations: Contributor, Person, Organization, Affiliation, Contribution and ContributorIdentifier. It also covers the profile helper functions, the profile editing forms and the transform classes. It does not cover the contribution levels and the permission checks built on them, which are in Contribution levels and record access, the methods that change who is credited on a record, which are in Crediting, or the claiming functions, which are in Profile claiming. The reasons behind the design are in How contributor accounts and credits work.

Every class below is imported from fairdm.contrib.contributors.models unless a section says otherwise. The generated Python API holds the docstrings.

Who may edit a profile#

Contributor.is_editable_by(user) is the one rule that decides who may open and save the profile editing page. It is not a Django permission, because the answer depends on the record.

Profile

is_editable_by(user) is true for

A person

The person, while their account is active. An active holder of the Community Manager role, when can_sign_in() is false for the person

An organization

An active user who passes is_managed_by(user) (a current administrator or owner), and an active holder of the Community Manager role, whether or not the organization has an owner

An anonymous visitor, a superuser and the holder of any other portal role get no right from that alone. The rule asks PortalRoles.is_held_by, never a Django permission. See Portal roles in code.

Management of an organization#

manage_organization is derived, not stored. OrganizationPermissionBackend answers user.has_perm("contributors.manage_organization", organization) as follows:

  • For an inactive user or a visitor, it answers false.

  • For a superuser, it answers true.

  • For anyone else, it answers true only when they hold a current OWNER affiliation with the organization.

A stored django-guardian grant of this permission is never consulted. Setting end_date on an affiliation, changing its type away from OWNER, or deactivating the account removes the right on the next check.

Contribution.Meta orders rows by object_id and order.

Two rules protect the data:

  • A named constraint, unique_contribution_per_contributor_object, allows one row for each contributor and record. clean() refuses a second row with the message This contributor is already credited on this object.

  • A role from any other vocabulary is refused before it is written: roles.add() and roles.set() raise ValidationError.

The roles a record’s type offers are the collection named by its CONTRIBUTOR_ROLES attribute, the address of one of the contributor roles vocabulary’s collections.

Profile forms#

fairdm.contrib.contributors.forms.profile holds the forms behind the profile editing page and the field their lists are typed into. The page is the Update plugin in fairdm.contrib.contributors.plugins.update. It reads FAIRDM_PROFILE_FORMS (see Settings) for the kind of contributor, person or organization, and falls back to the shipped form when the setting names none. It declares its own check, contributor_is_editable, so a visitor is sent to sign in and a signed-in user who may not edit gets a 403. The check runs on every request, so a right lost while the page is open refuses the save.

ProfileForm#

ProfileForm is the base of the two shipped forms. A portal’s own form can extend it. It draws no <form> tag, because the editing page supplies the tag and the buttons.

Attribute

Type

Default

What it does

sections

tuple of (heading, rows)

()

Groups the fields in page order. A row is one field name, or a tuple of names drawn side by side on a wide screen. A heading of None draws the rows with no heading

A field the form does not carry is left out of its section. A section left with no field is not drawn. A field that no section names is drawn after the last section.

A stored record can fail the model’s validation on a field the form does not carry, such as an identifier stored in a malformed state. ProfileForm reports that failure as an error on the form as a whole, in form.non_field_errors(), and saves nothing.

LinesField#

LinesField(entry_validator=None, max_entries=50, **kwargs) is a CharField on a text area whose cleaned value is a list. It trims each line, drops empty lines and keeps a repeated entry once, where it was first typed. A list given as the initial value is shown one entry per line.

from django.core.validators import URLValidator

from fairdm.contrib.contributors.forms.profile import LinesField

websites = LinesField(
    required=False,
    entry_validator=URLValidator(schemes=["http", "https"]),
    error_messages={"invalid_entry": "%(entry)s is not a web address."},
)
websites.clean("https://example.org\n\nhttps://example.org\nhttps://example.net")
# ['https://example.org', 'https://example.net']
